# 條件式命題與驗證設計

[理論框架](theory-case-bridge.md) · [主張清單](../evidence/claims-register.csv)

以下是 2026 年回溯分析提出的研究命題與驗證方案，沒有既有測試結果。命題的目的在於使解釋可以接受檢驗，而非將假說寫成企業成果。

## P1：辨識技術徵用的條件

**命題**：若使用者將既有工具用於原設計用途以外的客戶任務，且該用途形成可辨識的重複實踐，則個案可支持徵用的解釋。

- **依據**：E06 提供模式借鏡線索，但沒有完整用途改變的事件。
- **觀察單位**：具體的工具使用事件與後續實踐。
- **蒐集方式**：比較設計說明、實際操作及使用者敘述，確認原用途、行動者、改變內容與使用情境。
- **削弱訊號**：僅採用標準功能、只修改外觀，或新用途沒有證據可重建。
- **不能推論**：即使徵用成立，也不等於服務成效或競爭優勢成立。

P1 是概念辨識命題，不是徵用對企業績效的因果檢定。

## P2：內容重用與分散需求

**命題**：若可重用的內容能被有差異需求的客群找到，則小眾題材的重複使用可能增加，其商業意義取決於增量服務成本。

- **依據**：E02、E07。
- **觀察單位**：題材、任務與客群在事先約定期間的使用紀錄。
- **蒐集方式**：先定義題材分類與熱門／尾端口徑，再比較使用分布、回訪與相應成本。若條件允許，可比較不同內容發現方式。
- **削弱訊號**：流量增加僅出現在熱門題材；小眾內容沒有後續使用；額外成本抵銷貢獻。
- **不能推論**：總會員增加、一般會員增加或讀取次數增加，都不單獨證明長尾價值。

此命題把發現內容、持續使用與成本分開檢視，避免把不同結果壓成單一成功指標。

## P3：協作安排與服務連續性

**命題**：在重用既有研究與數位系統的服務中，若內容更新、客戶歸屬與交接責任明確且實際執行，則重複交接與未解決問題可能減少。

- **依據**：E03、E04、E07、E08。
- **觀察單位**：內容更新及跨部門服務事件。
- **蒐集方式**：記錄交接次數、等待時間、問題是否重開，並以訪談確認責任規則是否實際採用。
- **削弱訊號**：規則存在但沒有實行；交接負擔未改善；新增部門導致更長等待。
- **不能推論**：組織圖、新部門或制度文件的存在，不能替代實際運作證據。

若出現改善，還需檢查案件複雜度、工作量與人力變動，避免把所有變化歸於協作安排。

## P4：能力累積與相對客戶價值

**命題**：在同業功能相近的條件下，若研究更新與跨部門回應方式具有累積性，則特定客戶任務的完成與持續使用表現，仍可能保有相對差距。

- **依據**：E08、E09。
- **觀察單位**：可比較的服務任務、客群與一段持續觀察期間。
- **蒐集方式**：先界定競品和任務，記錄內容品質、回應方式及客戶結果，並追蹤相近功能出現後差距是否保留。
- **削弱訊號**：差距在功能被模仿後迅速消失；替代服務表現相當；所謂獨有能力無法提出運作證據。
- **不能推論**：短期任務表現或留存差異，仍不足以單獨證明持續競爭優勢。

P4 評估的是優勢的可能機制與中間結果，不以優勢存在當作優勢成立的證據。

## 衡量口徑示例

| 指標 | 操作定義 | 主要限制 |
| --- | --- | --- |
| 任務完成率 | 成功完成預定任務的人次／嘗試人次 | 須先定義任務及成功標準 |
| 重複使用率 | 在後續期間再次使用者／初期使用者 | 期間長度及客群組成影響解讀 |
| 尾端內容使用占比 | 事先分類為尾端的有效使用次數／全部有效使用次數 | 不能事後依結果改變分類；占比不等於收益 |
| 每位活躍客戶增量成本 | 同期額外內容、審核、支援及維運成本／活躍客戶數 | 成本與活躍口徑需要一致 |
| 問題解決時間 | 同類服務事件從提出至解決的時間 | 需納入難度、工作量與重開案件 |
| 客戶價值回饋 | 針對特定任務的滿意度及使用原因 | 自陳回饋應與操作紀錄交叉檢視 |

## 比較與訪談設計

1. 選定單一客群與任務，先確認現有流程、資料授權及成本口徑。
2. 在可行情況下使用同期對照或分批推出。若只能前後比較，需記錄市場、行銷、內容供給及客群變動。
3. 訪談研究、業務、科技及服務人員，要求敘述具體事件、決策與反例，再與文件及紀錄核對。
4. 找出沒有採用、放棄使用及使用失敗的情況，避免只選成功故事。
5. 由資料與責任單位事先約定擴大、調整或停止條件。本案沒有替企業虛構目標值。

即使多種資料彼此一致，也仍需評估替代解釋。此設計未執行，不能據此宣稱本案具有已完成的實證研究結果。
